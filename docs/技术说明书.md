# AI工具管理器 · 技术说明书

版本：1.0.0
日期：2026-10-18

## 1. 技术选择

Windows 原生 WPF 界面；C# 管理窗口、卡片、设置和文件监听；嵌入的 Windows PowerShell 模块负责发现与本地资料提取。使用系统 .NET Framework、Windows PowerShell 5.1 与 C# 编译器，不依赖 VS Code、Node.js、Python、NuGet 或 .NET SDK。

运行目标为 Windows 10/11，已实测当前 Windows 11 环境。企业策略或被移除的系统组件可能限制运行。EXE 采用普通用户权限，不申请管理员权限。

## 2. 源码结构

~~~text
src/Program.cs          WPF 事件、后台任务、设置、监听、安全动作与集成自检
src/MainWindow.xaml     工具库、左侧导航、独立详情页
src/Inventory.ps1       发现、分类、状态、身份和扫描报告
src/Metadata.ps1        JSONC 与本地说明提取
src/app.manifest        asInvoker、Windows 兼容与 DPI 声明
src/app.ico             应用图标
tools/Build.ps1         系统编译器构建与资源嵌入
tests/Scanner.Tests.ps1 隔离扫描与只读测试
tests/Run-Tests.ps1     扫描测试和真实 EXE 集成测试
VERSION                 正式语义版本号
~~~

## 3. 运行架构

~~~mermaid
flowchart TD
 UI[WPF 主线程] --> TASK[后台 Task]
 TASK --> PS[独立 PowerShell 实例]
 PS --> INV[Inventory 发现与状态]
 INV --> META[Metadata 资料提取]
 META --> JSON[扫描报告 JSON]
 JSON --> DISPATCH[Dispatcher 更新界面]
 FS[FileSystemWatcher] --> DEBOUNCE[事件静默窗口]
 DEBOUNCE --> UI
 TIMER[60 秒补充核对] --> UI
~~~

主线程不执行遍历，使用 Task 和独立 PowerShell 实例读取资料，返回 JSON 后通过 Dispatcher 更新。序列化器的后台解析实例与 UI 设置写入实例分开，避免共享状态竞争。

EXE 嵌入 MainWindow.xaml、Inventory.ps1、Metadata.ps1 和 app.ico。运行不从旁边的 src 目录执行脚本；单独复制 EXE 后仍可运行。Windows PowerShell 运行库来自系统组件。

## 4. 数据模型

| 字段 | 含义 |
| --- | --- |
| Id | 分类、路径、名称组合规范化后生成 SHA-256 截取标识，用于快照比较 |
| Name / Title | 原始工具名 / 可提取的展示标题 |
| Category | skills、mcp、plugins、projects、apps、downloads |
| Status / Note | 具体发现情况 / 尚未检测的事项 |
| Client | 来源客户端或发现范围 |
| Path | 准确文件、目录或注册表登记路径 |
| Evidence | 形成记录的依据 |
| Modified | 文件或目录修改时间，用于变化识别 |
| Description / Usage | 说明与使用方法，可为本地文档摘要或明确的类型引导 |
| DocPath / DocSource | 原始文档路径与来源描述 |
| RepositoryUrl | 经清理的 GitHub HTTPS 项目地址 |

扫描报告还包括 Roots、Warnings、Directories、Cancelled 和 ScannedAt。不会返回 MCP 命令、环境变量、密钥或完整配置。

## 5. 发现逻辑

### 5.1 范围与预算

默认目录与深度：.codex 10、.claude 8、.agents 5、.cursor 4、.windsurf 4、.vscode/extensions 1、Downloads 3、source/repos 3。自选目录深度 6；单轮上限 15000 个目录。深度从根目录继续向下计算，根本身也会检查。

正常用户上下文中优先使用 USERPROFILE；下载目录在可读取时采用当前用户 Shell Folders 的重定向路径。测试可显式指定隔离 HomePath，不混入真实下载目录。

不跟随目录重解析点，跳过依赖、构建、日志、会话、临时和已知凭据目录。访问失败生成提示，不中止所有扫描。文档与配置单文件上限 2MB。

### 5.2 配置与清单

JSONC 预处理按字符串/转义状态去除注释和尾逗号，避免把 URL 中的双斜线当注释。TOML 采用面向 MCP 常用服务表的限定解析，不声称覆盖完整 TOML。明确的 enabled=false 或 disabled=true 可形成禁用状态；未知值不推断为禁用。

已知配置位置与递归发现的示例/附带配置分开表达。插件配置和文件清单也是不同证据，不能相互替代。

### 5.3 应用与项目

应用来自当前执行上下文可读的 Windows 卸载登记、Appx 包和常见命令入口；不会使用 Win32_Product，避免触发 MSI 检查或修复。源码项目来自 Git 标记，或下载/自选目录中的 README 与项目清单。GitHub URL 只保留匹配到的 owner/repo，不携带用户名、密码或令牌，也不访问远程。

## 6. 说明提取

支持 SKILL.md 常用 YAML name/description 标量与折行说明；插件 description/displayName；README 的正文摘要与 Usage/使用/快速开始段落。采用限定字符数，按纯文本显示，不执行 Markdown、HTML、脚本或文档指令。

缺少或无法读取说明时，回退到类型层面的引导，保留来源提示。没有联网 AI 自动解释层；部分常见软件简介属于内置说明。

## 7. 刷新、差异与监听

完整扫描完成后以 Id 比较前后快照：新增、未再发现、资料/状态变化。首次盘点仅建立基线。记录本次会话最近 250 条变化。“未再发现”不推断为确定卸载。

取消标记使用同步 Hashtable，由扫描循环定期检查；取消或失败不以部分结果替换上次完整清单。

FileSystemWatcher 的文件名、目录名、修改时间与大小事件只更新原子时间戳；主线程定时器在静默约 1400ms 后发起扫描。扫描进行中不并行启动另一轮，之后可处理待定变化。每 60 秒补充核对，覆盖注册表等缺少文件事件的变化。监听失败提示用户仍可手动刷新。

## 8. 设置与导出

便携设置位于 EXE 旁 Data/settings.json，包含 ExtraRoots 与 AutoUpdate。通过临时文件写入后替换本工具设置；失败显示提示。不会在仓库提交这些设置。

JSON 导出包含清单资料；CSV 对可能被表格软件解释为公式的前导字符加保护。导出由用户选择目标，覆盖需确认。

## 9. 安全动作

- 路径复制：Clipboard。
- 文件夹定位：仅允许本机磁盘路径，存在性检查后打开 Explorer，不执行条目本身。
- 原始文档：只读文本窗口，检查大小和文件链接属性。
- 项目链接：仅允许清理后的 github.com HTTPS 地址，由用户点击打开。
- 桌面快捷方式：用户主动点击后通过 Windows Shell 创建；同名存在时确认更新。测试仅在隔离目录验证。

没有修改客户端配置、自动执行工具、安装依赖、网络上传、遥测、后台服务或开机任务。

## 10. 构建与版本

标准入口为 tools/Build.ps1。选择系统 Framework64 编译器，必要时回退 Framework，引用系统 WPF 与 PowerShell 程序集，嵌入资源，生成 AI工具管理器.exe。

1.0.0 对应程序集与文件版本 1.0.0.0；界面显示本地版 1.0；VERSION、README、发布说明和验证记录保持一致。构建本身不修改真实客户端目录。

## 11. 验证与限制

扫描测试使用隔离材料验证 17 项；原生 EXE 集成验证 16 项，涵盖跳转、刷新、实际文件事件、文档变化、设置保存和隔离快捷方式。另验证 EXE 脱离源码目录启动。

如后续增加 GitHub Actions，建议仅运行构建和扫描测试，不把托管运行器视为完整交互桌面环境。本版本尚未配置或验证远程 CI。原生窗口验证需在可用 Windows 桌面运行 tests/Run-Tests.ps1。

已知限制：有限的配置适配、有限的应用名称匹配、不解析任意压缩包内部、没有连接/健康检查、没有跨用户或 WSL 支持。Windows 10 仍需独立设备兼容性验证。
